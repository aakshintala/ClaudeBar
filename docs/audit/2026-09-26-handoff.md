## Ranked queue

Order = value divided by risk, adjusted for dependencies. Tier A fixes wrong behaviour. Tier B is compiler-guarded deletion. Tier C is structural. Tier D is performance polish that measurement showed is cheap today.

### Tier A: correctness and security

**1. One refresh path through `QuotaMonitor`; background sync currently refreshes only Claude** (M; decision 1)
- `StatusBarIconDriver.swift:109-111` hard-codes `backgroundRefreshProviderIds` to `nil`, so the loop calls `refreshSelected` (`QuotaMonitor.swift:274-276, 336-339`). `selectedProviderId` defaults to `"claude"` (`:48`) and no UI changes it. Background sync never refreshes Codex, Cursor or OpenCode.
- `PopoverView.swift:56-64, 73-75, 117-121` calls `provider.refresh()` directly and one at a time, skipping `isAvailable` and `handleSnapshotUpdate`. Popover refreshes never fire alerts, and every popover open re-probes Cursor, Codex and OpenCode with no freshness check.
- Nothing coalesces across the popover, the feed (`QuotaFeedService.swift:35-49`) and the loop. `isSyncing` is a single Bool, so concurrent refreshes clear it early.
- Change:
  - `QuotaMonitor.refresh(force:)` refreshes all enabled providers concurrently, skips any snapshot younger than about 60 s unless `force`, and joins in-flight work through `[id: Task]`.
  - Popover `.task` calls it; the refresh button passes `force: true`; the feed and the loop call it.
  - Delete the selection surface: `selectedProviderId`, `selectedProvider`, `selectedProviderStatus`, `selectProvider`, `selectFirstEnabledIfNeeded`, `refreshSelected`, `refreshOthers`, `addProvider`, `removeProvider`, `isRefreshing`, `lowestQuota`, `overallStatus`, `quota(providerId:quotaKey:)` and `provider(for:)`.
  - Also delete the `providerIds` loop option, the `RefreshLoopKey.providerIds` field, and the `AsyncStream<MonitoringEvent>` (the app drains it with `for await _ in stream {}`; `.error` is never yielded).
- Delta: Sources about −200, Tests about −600 (`ProviderSelectionSpec`, selection and add/remove sections of `QuotaMonitorTests`).
- Guard: write the failing test first. A background tick refreshes every enabled provider, and a popover refresh fires an alert. Existing guards: `RefreshSpec`, `NotificationsSpec`, `QuotaMonitorTests` "Continuous Monitoring" and "Energy Awareness".
- Enables: 11 (`AIProviderRepository` deletion), 11, 16.

**2. Keychain write puts the OAuth credential JSON in argv** (S)
- `ClaudeCredentialLoader.swift:276`: `security add-generic-password -s <service> -w <jsonString>`. Any local process can read it from `ps` while it runs. It also runs delete then add (`:262-271`) where an in-place update would do.
- Change: use `SecItemUpdate`, falling back to `SecItemAdd` on `errSecItemNotFound`, from the Security framework. Consider the read path too (`:214-228`, `security find-generic-password`), so there are no subprocesses for Keychain at all. That also removes a per-5-minute spawn.
- Guard: `ClaudeCredentialLoaderTests` (the Keychain paths may need a seam; check what exists first).

**3. Codex RPC transport loses buffered lines, then hangs and leaks `codex app-server`** (M)
- `ProcessRPCTransport.swift:47-55`: each `receive()` creates a new `fileHandleForReading.bytes.lines` iterator. `AsyncBytes` reads ahead, so any second line in the same chunk is discarded. If a notification and the response arrive together, `DefaultCodexRPCClient.request` (`:258-276`) waits forever, and `close()` in the `defer` never runs. `receive` has no timeout.
- Compounding: `QuotaFeedService.swift:46-59` races refreshes against a 20 s deadline inside `withTaskGroup`, which still awaits every child. Probes stuck in `waitUntilExit` or `receive` ignore cancellation, so `inFlightRefresh` stays set and every later `GET /quotas` hangs on it.
- Change:
  - Store one `AsyncLineSequence` iterator in the transport.
  - Give `receive` a timeout of about 10 s that terminates the process.
  - In `QuotaFeedService`, race an unstructured `Task` against a sleep with first-to-resume, and always clear `inFlightRefresh` at the deadline.
- Runtime check: in RPC mode, `pgrep -fl 'codex.*app-server'` after several refreshes (expect 0 at idle). `kill -STOP` the app-server, then `curl -m 60 127.0.0.1:8787/quotas` twice; after the fix both return by about 20 s.
- Guard: `DefaultCodexRPCClientTests` plus new transport tests (two lines in one write; a silent peer).

**4. Reset times: Codex RPC drops the date, and the other probes bake stale strings** (S–M; decision 4)
- `DefaultCodexRPCClient.swift:220-226` turns `resetsAt` into a string, and `CodexRateLimitWindow` has no date. RPC-mode Codex quotas therefore have `resetsAt == nil` (`CodexUsageProbe.swift:72-88`). The popover shows "—", and pace-aware status falls back to absolute thresholds for Codex.
- Claude (`ClaudeAPIUsageProbe.swift:596-613`) and Codex API (`CodexAPIUsageProbe.swift:329-347`) bake "Resets in 1h 24m" into `resetText` at probe time, and it is then served from cache. Three copies of the same formatter.
- Cursor puts request counts into `resetText` (`CursorUsageProbe.swift:270, 290, 312`), duplicating `unitsUsed`/`unitsLimit`. `QuotaFeedText.swift:67-73` then strips them out again with a regex.
- Change: probes set only `resetsAt: Date?`. Delete the 3 formatters and `UsageQuota.resetText`. One formatter at the edge (`compactResetTime` plus the DTO).
- Delta: Sources about −90, Tests about −40.
- Guard: `QuotaFeedTextTests`, `QuotaFeedDTOTests`, `DefaultCodexRPCClientTests.parseWindow`, `CodexUsageProbeTests`.
- Do after 10 (the `UsageQuota` deletions), to avoid editing lines about to go.

**7. Subprocess helper: read before wait, honour QoS, stop blocking the cooperative pool** (S–M)
- Six copies of "spawn, `waitUntilExit()`, then `readDataToEndOfFile()`": `CursorUsageProbe.swift:97-128`, `ClaudeCredentialLoader.swift:214-293` (3), `BinaryLocator.swift:78-107, 158-195`. Output larger than the pipe buffer (64 KB) deadlocks. Each wait blocks a Swift cooperative thread.
- `ProbeExecutionContext.qualityOfService` only reaches `InteractiveRunner.swift:219`. `ProcessRPCTransport`, `sqlite3`, `security` and the login shells run at default QoS.
- Change: one `runProcess(_:args:) async throws -> (status, stdout)` that reads to EOF before waiting, uses `terminationHandler` plus a continuation, and sets `qualityOfService`. Memoise `BinaryLocator.which(_:)` and `shellPath()` for the life of the process, clearing an entry on a not-found launch failure. Each RPC-mode Codex refresh currently starts about 3 `zsh -l` shells (`DefaultCodexRPCClient.swift:29-33`, `ProcessRPCTransport.swift:16, 25`).
- Delta: Sources about −100.
- Runtime check: `sudo fs_usage -f exec -w | grep -E 'zsh|path_helper|codex|sqlite3'` during an RPC-mode refresh, before and after.
- Do after 2, which removes the `security` calls.

**8. Codex credits budget is invented** (S; confirm intent)
- `CodexAPIUsageProbe.swift:277` hardcodes `limit: Decimal = 1000` and reports `used = 1000 - balance`. A balance above 1000 shows 0 used; the percentage is meaningless. Either show the balance alone or find the real grant in the API response.

### Tier D: performance polish (measured cheap today)

**23. Small runtime costs** (S each; independent)
- **Cursor:** cache the access token until the JWT `exp` claim (already decoded at `CursorUsageProbe.swift:131-158`) or a 401. That removes one `sqlite3` spawn per Cursor refresh.
- **FileLogger** (`FileLogger.swift:45-96`) does `attributesOfItem` + `fileExists` + open/seek/write/close and builds a new `ISO8601DateFormatter` for every line. Keep one handle and one formatter, and check size every N writes.
